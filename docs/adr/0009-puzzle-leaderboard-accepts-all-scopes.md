# 拼图成绩接受全部范围，不再限于「世界全国」与「全国市级」

拼图排行榜最初只放开两个范围：**世界全国**（194 片）与**全国市级**（340 片）。当时（2026-09）的用户口径是「其余范围——省级全国、大洲、次区域、下钻某省——不弹结算也不进榜」，理由是这些范围片数少、几分钟就能拼完，榜的区分度低。

这个口径与**默认入口**相撞了：拼图模式的档位是本地记住的，首访默认**省级**，而省级全国（34 片）恰好落在"不进榜"的那一档。于是新用户的第一局必然是：拼完**没有「提交成绩」按钮**（`collectResult()` 因范围不合格返回 null）、右侧排行榜**永远是空的**（服务端白名单根本不接受那一档，`GET /api/leaderboard?mode=puzzle&scope=__province_nation__` 结构上只可能返回空数组）。一次真实反馈把它当成"功能没做"报了上来。

现在改为**所有合法范围都可提交**：世界全国、省级全国、全国市级、大洲、次区域、下钻某省，各自按**范围哨兵**（`__world_nation__` / `__province_nation__` / `''` / `__continent_XX__` / `__subregion_XXX__` / 6 位 adcode）独立成行。范围合法性不在拼图分支里另开一份名单，一律复用既有的 `normalizeScope()` 白名单——原先前后端各写一份 `PUZZLE_SCOPES`/`isPuzzleLeaderboardScope`，两份名单一旦漂移就是"界面能交、服务端静默拒绝"。

其余口径不变：排名一律**已拼个数优先、个数相同比用时**（`correct` 列存的就是「已拼」= 1 + 吸附次数），门槛仍是**已拼 ≥ 2**，与答题模式的同范围榜互不覆盖（`UNIQUE(user_id, mode, scope_province)`）。

**Status**: accepted

**Consequences**:

- **这是一处持久化契约变更，且不可回退**：新范围下写进 D1 的行一旦产生，再把范围收窄回去就会让它们成为孤儿（`docs/adr/0001` 的同一条规则）。这些范围此前**从未有过**拼图成绩，所以放开本身零迁移、零冲突。
- 片数差异极大（下钻某省最少 4 片、世界全国 194 片），同一套排名语义下它们的含金量不同。这是接受的代价：范围写在 `scope_label` 里、榜标题也写明范围，用户看得见自己排的是什么。
- 「重置 → 结算卡片」现在在**所有范围**都会弹（原先按 `isRankedScope()` 限制）。已拼 < 2 时 `collectResult()` 仍返回 null，卡片不弹、直接回开始卡片——这条门槛没有变。
- 服务端白名单在 `functions/_lib/validate.ts`，改动后**必须重新部署 Cloudflare Functions**，否则线上仍会拒绝新范围的成绩。
- 顺带修掉一处不一致：拼图模式的初始范围曾经硬编码为 `PROVINCE_NATION_SCOPE`，而档位是本地记住的——上次用过世界/市级的话，重开页面会出现"地图画的是世界/市级、排行榜却按省级全国去查"（查的正是那张永远空的榜），市级档下开始卡片还会把 `__province_nation__` 这串内部字符串印给用户。现在范围一律由档位推出。

# 0011 「其他」档取「他国一级行政区」，独立成第四族且不计分

## 状态

已采纳（2026-10）。

## 背景

用户需求：输入模式与点击模式的「世界/省级/市级」右侧加「其他」，点进去可选
**美国 / 加拿大 / 日本 / 俄罗斯**，用这些国家的**一级行政区**（对应中国的省级）作答题内容，
并支持「中文 / 当地语言」切换（美加英语、日本日语、俄罗斯俄语）。
用户追加确认：争议地区**不考但显示**；**纯练习**（不计熟练度、不上排行榜）；飞地放**左下角小窗**；
本轮只做输入与点击两个模式。

## 决策一：独立成「第四族」，而不是塞进世界档

现有三档粒度（世界 194 国 / 省级 34 省 / 地级 373 市）各自有自己的投影、题池、相邻关系与
熟练度分区。「他国一级行政区」是**第四类几何**：

- 它要**按国家单独投影**（世界图的投影范围是固定的 [-180,-90]..[180,83.6]，一个州或一个
  都道府县在那上面只有几个像素，无法点击也无法辨认）；
- 它有自己的**相邻关系**（顺序出题要按陆地邻接走，见 ADR 0005 的同一动机）；
- 它的**region 名不能用名字**：显示名随语言变（中文/当地语言），而 ECharts 按 `properties.name`
  匹配 region。故这一族的 GeoJSON 在加载时把 `properties.name` 改写成**编码**（`US-CA`），
  于是"切语言"只影响一个取文本的函数，不动任何几何。

反例（被否）：把它们并进世界档。那会让世界档的每个分支都要判断"这次的面到底是不是国家"，
而世界档有一条被大量验收脚本依赖的固定契约（195 国、装饰面、大洲/次区域下钻）。

## 决策二：纯练习 —— 不写熟练度、不上排行榜

用户口径明确："两者都不计"（不计熟练度、不进排行榜）。实现上：

- `MapQuizMode.recordPractice()` 在这一档**不调 `MemoryStore`**，熟练度分析的四个分区都不受影响；
- `collectResult()` 返回 `null` → 不弹可提交的结算卡、不调 `/api/score`、`getScopeProvince()`
  返回 `null` → 没有榜单作用域。

但**「错题」分段按钮是输入/点击模式原有的功能**，一条都不记会让那个按钮永远选出空池。
故错题记在**独立的一份清单**（`china-admin-other-wrong:<mode>`，见 `src/other.ts`），
它不进 `MemoryStore`、不参与任何成绩提交。"不计分"与"记得你错过"是两件事，用户要的是前者。

## 决策三：争议地区「不考但显示」

该数据源把克里米亚与塞瓦斯托波尔（`UA-40`/`UA-43`）划给俄罗斯。用户口径是"不考但显示"：

- 两者**保留在几何里**（地图上照常画出来，避免"地图缺一块"这种更强烈的表态）；
- 但**不进题池**（`decorative: true`，不可交互、不出题、不计入题数）——
  与既有"装饰面"（南海诸岛、属地、南极）同一套机制，见 ADR 0005。

俄罗斯因此是 **85 个面 = 题池 83 + 不考 2**。

## 决策四：飞地放左下角小窗（与港澳放大框同一套做法）

阿拉斯加、夏威夷、加里宁格勒远离国土主体。若都塞进主图，主图投影被拉宽数倍、本土各州各州
只剩几个像素（美国本土 48 州会被压成半屏）。

做法：显式清单（构建期 `insetGroups`，不是几何启发式 —— 实测"连通分量"在日本的四个大岛之间
也没陆地相邻，会被误判成"四块飞地"），每块飞地**一个小窗**；小窗视觉与港澳放大框同一套
（同边框/圆角/底色/阴影），说明与缩放按钮自动让位。美国给**两个**窗（阿拉斯加、夏威夷各一个）：
两者相距 4000 多公里，合在一个窗里两块各占对角、都只剩几个像素。

## 决策五：判题按「精确 > 归一化 > 前缀」打分

中文名带行政后缀（加利福尼亚**州**）、日文带都道府县、俄文有「Республика X」这种**前缀**式写法，
而用户会少写后缀、打不出长音符号、大小写随意。故归一化后比对，并接受**三种写法**
（中文名 / 当地语言名 / 英文罗马字），与当前语言档无关。

⚠ 但**不能只做"归一化后查表"**：剥掉后缀后源数据里有**两对**名字会撞车 ——
`阿尔泰共和国`/`阿尔泰边疆区` 都剥成「阿尔泰」、`莫斯科`/`莫斯科州` 都剥成「莫斯科」。
只做相等判断会把用户答对的「阿尔泰边疆区」判成阿尔泰共和国（`src/other.test.ts` 的
真实数据全覆盖用例当初就是这么抓出来的）。故分三档取最高分，并列时优先**当前题目**
（输入模式把 `question` 传进判据）。

## 决策六：几何按国家懒加载

四国几何合计 567KB（美 133 / 加 203 / 日 47 / 俄 183），而一次只练一个国家。
塞进启动加载会让每次打开站点都多拉 567KB（比中国地级细档还大），而绝大多数访问根本不碰这一档。
故：1KB 的四国清单随启动加载（分段按钮要立刻可点），具体某国的几何在**点那个国家时**才拉，
并顺带注册它的 ECharts 地图。

## 后果

- 新增一条**数据管线**（`scripts/fetch-other-admin1.mjs`）与一份**逐条纠错兜底表**：
  源数据里 `RU-MOW`/`RU-MOS` 的编码与几何是**互换**的、`RU-ARK` 的当地名与 `RU-ALT` 的俄文名
  各错一条、`RU-AL`/`RU-ALT` 中文重名、两处繁体残留、东京缺「都」、一条属性全空的残留面；
  跨 180° 经线的单位（楚科奇、阿留申）需要按国家参考经度**解缠**。这些都由
  `src/otherData.test.ts` 的 40 条断言守着。
- 渲染器多一族（`setOtherMode` / `other-labels` / `focusOtherUnit` / `panOtherUnit` /
  取景边界 = 该国包围盒），`Granularity` 多一个取值 `'other'`，口径注册表多一组 `other`
  （中文/外语，两档共用同一判据）。
- **已知边界**：日俄两档的"英文名"用的是源数据的**罗马字**（莫斯科是 `Moskva` 而非 `Moscow`、
  阿尔泰共和国是 `Gorno-Altay` 而非 `Altai Republic`）。若要让常见英文名也算对，需要另加别名表。
- 后续要加国家（如德国、印度）只需重跑数据管线 + 在 `COUNTRIES` 里加一行：UI 的国家按钮
  由数据渲染，模式、渲染器、判题都不用改。
